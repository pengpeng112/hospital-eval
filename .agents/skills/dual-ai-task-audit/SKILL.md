# 双 AI 接力任务回执核查与裁决同步技能

本技能用于主控 AI（Antigravity）对外部执行 AI 提交的 `TASK-01 ~ TASK-20` 产物进行独立质量门禁核查、问题裁决与下游任务前置排雷。

## 一、回执独立核查五步法（严禁仅看回执文字下结论）

1. **提交范围与脏文件核查**：
   - 运行 `git log --oneline -n 5` 与 `git show --stat <commit>`，核对改动文件是否严格落在 `docs/tasks/TASK_XX.md`「允许新建/修改的文件」白名单内。
   - 检查工作区根目录是否存在未跟踪的异常目录或临时文件（如路径转换残留 `;D`、误落盘的 `.csv`/`.xlsx`、`maven-repo`）。
2. **安全与隐私红线扫描**：
   - 确认 `deploy/.env`、`*.csv`、`target/`、`node_modules/` 未入库；扫描新增提交与回执文本，确保**零明文密码/密钥/账号**、**零患者姓名/住院号/身份证号**。
   - 涉及后端任务时，实测宿主机 `java -version` 仍为 `1.8.0_292`。
3. **关键逻辑代码审阅**：
   - 按 `04_开发契约与编码规范.md` 核对核心边界逻辑（如 SQL 只读沙箱拦截、左闭右开时间窗、`PATIENT_ID + VISIT_ID` 全院去重、三级复核状态机与权限注解）。
4. **验收命令与冒烟独立重跑**：
   - 亲自重跑 `TASK_XX.md` 中的单元测试、数据校验或 `scripts/smoke/TASK_XX.ps1`，将实测输出数字与 `docs/task_receipts/TASK_XX_回执.md` 逐项比对。
5. **N+1 / N+2 下游任务前置排雷（Look-Ahead）**：
   - 核查通过前，读取紧邻的下一任务说明书（`TASK_(XX+1).md`），结合当前数据库真实数据分布与本机网络状态，预判是否存在会让弱执行模型卡死的隐患（例如：同角色多条激活 SQL 年份重叠、Oracle 监听 IP 白名单未放行导致 `ping` 误判 `FAIL` vs `ORA-01017` 密码错误等），提前在契约与任务书中消解。

## 二、“待确认事项裁决清单”处理与原子同步规范

1. **先给裁决建议，获批或受权后再改文件**：
   - 逐条对照 `AGENTS.md` 与 `04_开发契约与编码规范.md` 核实执行 AI 所述事实是否成立，给出明确的【同意 / 修正方案】及理由。
2. **主控统一跨文件同步（因执行 AI 受白名单限制不能改契约）**：
   - 用户确认后，由主控 AI 在一次独立提交（`chore:` 或 `docs:`）中原子同步：
     - `04_开发契约与编码规范.md`（唯一权威契约）；
     - 所有受影响的后续 `docs/tasks/TASK_*.md`（命令参数、边界规则、冒烟判据）；
     - 必要的编排文件（如 `deploy/docker-compose.dev.yml`）或幂等迁移脚本重跑校验。
   - **并发保护**：若 `git status --short` 显示外部执行 AI 已并发开始编写下一任务文件，严禁执行 `git add -A`、`git clean` 或重启后端容器，仅用路径限定方式（`git add -- <paths>` + `git commit -m "..." -- <paths>`）提交主控改动。
   - 非并发场景下，同步完成后运行最新冒烟脚本与 `git status --short`，确保工作区完全干净再交棒给下一任执行 AI。
