### 部署过程中排障（两处，均已解决并固化）

1. **firewalld 拦截容器网络**：openEuler 默认 firewalld public 区（ens9）不信任 docker 网桥（172.18.0.0/16）→ eval-server 崩溃循环（`NoRouteToHost` 连 eval-postgres:5432）、eval-web 502。处置：`firewall-cmd --permanent --zone=trusted --add-interface=docker0 / br-84e2a18802e8` + reload + 重启 docker（仅信任新建的 docker 网桥接口，未开放任何对外端口）；
2. **eval-web 首页 500（nginx 内部重定向死循环）**：eval.conf 漏写 `root /usr/share/nginx/html;`（开发态由 vite 托管从未暴露）→ try_files 兜底 /index.html 相对默认前缀 /etc/nginx 永远找不到 → 死循环。处置：conf 补 root，重建 web 镜像重新 load + force-recreate eval-web。

### 数据迁移（pg_migrate.ps1，二进制安全流程）

- **教训**：PS 5.1 的 `>` 重定向把 `pg_dump -Fc` 二进制流按文本解码重编码 → 归档损坏（"not a valid archive"）；已固化为容器内 `-f` 落盘 + `docker cp` 拷出 + `pg_restore -l` 校验的流程（脚本已按此重写）；
- dump 110,821,434 字节 → `/opt/hospital-eval/backup/eval_dev.dump` → `pg_restore --clean --if-exists`；
- 9 个 "cannot drop inherited constraint" 为分区明细表（INHERITS 结构）`--clean` 首次还原的固有非致命错误（errors ignored on restore: 9），数据完整。
